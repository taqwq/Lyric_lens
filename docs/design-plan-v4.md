# Lyric Lens デザイン設計 v4（実装前の設計案）

この文書は「実装する前に、ゼロからしっかり設計する」ための設計書です。目標は Apple の **品質と思想の深さ**であって、Apple の見た目をまねることではありません。

## 0. 前提（確認したいこと）

- **何を作るか**：Genius の歌詞ページで、英語の各行の真下に自然な日本語訳を差し込む道具。必要な行にだけ注を付け、曲の要点を2文で添える。
- **誰のためか**：英語が得意ではない、洋楽ヒップホップ／R&B が好きな日本の聴き手。曲を流しながら読む。スマホと PC の両方。
- **いちばんの仕事**：いま目がある行の意味を、原曲のリズムと声を壊さずにその場で分からせること。
  - 次に、曲全体をつかませること（前書き）。
  - その次に、隠れた意味を掘れるようにすること（注）。

## 1. どう決めたか

方向性を一つに決め打ちせず、4つの独立した設計案を並行して作り、同じ物差しで比べました。

| 案 | 中身 | 合計点（3人の評価） |
|---|---|---|
| **Genius になじむ案** | Genius 自身の黒いバー・角のない形・下線リンク・黄色を借りる | **121** |
| 第一原理 | 比喩なし。読みやすさだけから導く | 110.5 |
| 行間の訓点 | 振り仮名や漢文の注のように行に寄り添う | 104 |
| 国内盤の対訳 | 帯と対訳ブックレット。明朝体 | 103 |

- 評価したのは、デザインディレクター、実際の読み手、Genius でユーザースクリプトを作るエンジニアの3人です。
- 「Genius になじむ」はあなたが出したアイデアの一つで、ほかの案と同じ条件で比べました。結果、3人中2人が1位にしています。
- 「国内盤」の案も、独立に同じ「黒いバー」の形にたどり着いていました。
- 最終案は「Genius になじむ案」を骨格にして、ほかの3案から優れた部分を移植しました。移植の中身は §9 にまとめています。

## 2. 思想

> **聴きながら、わかる。**

読み手は曲を流しながら、このページを読んでいます。Lyric Lens の役目は、意味を**聴いている速さで**届けることです。そのあいだ、目も耳も曲から離させません。以下の判断は、すべてこの一文から出ています。

**四つの柱**

1. **意味は、目がある場所に。**
   - 訳は各行の真下に置く。注もその行の下で開く。
   - 操作は一か所にまとめる。
   - 目を横や別の窓へ動かさせない。
2. **流れを切らない。**
   - 画面が動くのは、自分で押した直後だけ。ポップアップも点滅もしない。
   - 役目を終えたら一歩下がる（黒いバーが白い行になる）。
   - 一度読んだ曲は一瞬で出る。
3. **覚えることを増やさない。**
   - 慣れたページの上で、新しい見た目を覚えさせない。
   - Genius 自身の文法で話す：黒いバー、四角、下線リンク、▾、黄色のマーカー。なじむのはこのためで、雰囲気のためではない。
4. **正直に。**
   - 訳は「AIによる日本語訳」と名乗り、Genius の人が書いた注釈と混ぜない。
   - 自信のない注は〔推測〕と言う。
   - 進み具合は本物の割合で見せる。止まったら、止まった場所に理由と次の一手を置く。

**柱から出てくる約束**

- **黒は、Lyric Lens があなたを必要としているとき、または動いているときだけ**（柱3・4）。終われば白くなり、Genius の行に溶ける（柱2）。
- **黄は「あなたが尋ねた言葉」だけ**（柱1・3）。Genius のマーカーの色を、この意味にだけ使う。
- **訳は本文**（柱1・2）。墨色で、各 OS のゴシックで組む。Web フォントは使わない。
- **指の下は動かない**（柱2）。バーの高さもリンクの位置も、どの状態でも同じ。

**いちばん記憶に残る瞬間**：注を開くと、歌詞の中の言葉・※・注の見出しが同時に黄になる。「どの言葉の話か」が、読まずにわかる（柱1）。

**国内盤の「帯」の比喩はやめた**：あれは作り手が気持ちよくなる物語で、読み手の役には立たない。見た目の判断はもともと比喩ではなく上の柱から出ているので、デザインはほぼそのまま残る。

## 3. 以前の案が「質が低い」と感じられた理由

- **A（罫線紙）**
  - 赤い文字のボタンに押せる感じがなかった。
  - 訳が灰色で、本文なのに脇役に見えた。
  - 点線が未完成に見えた。
- **B（線の丸ボタン）**：形を変えただけで、考え方が変わっていなかった。
- **C（Apple 風）**
  - 灰色の角丸カード、ピンクのボタン、灰色の読み込み中バーで、どこにでもある見た目だった。
  - 赤い文字リンクが散らばっていた。
  - Genius のページの文法と合っていなかった。
- **根本**：見た目のスタイルから入って、読み手の場面と Genius という土台から決めていなかった。

### 文字

- **英字と数字**：Genius が歌詞に使っているフォント（いまは Programme）を起動時に読み取って使う。行数（12/67）も Genius の数字で揃う。
- **日本語**：各 OS のいちばん良いゴシックを使う。
  - Mac/iOS は ヒラギノ角ゴシック。
  - Windows は BIZ UDPゴシック。Windows 10 1809 以降に標準で入っていて、游ゴシックの細さを避けられる。
  - Android は Noto Sans CJK JP。
  - それ以外は 游ゴシック UI、メイリオ。
  - **Web フォントは使わない**。明朝は、ラップの口語に合わないこと、スマホで読みにくいこと、Android に標準の明朝がないこと、2回目以降の表示がちらつくことから不採用。
- **すべての日本語に指定するもの**
  - `lang="ja"`
  - `line-break: strict`
  - `word-break: auto-phrase`（文節で折り返す）
  - `text-spacing-trim: trim-start`
  - 本文には palt を使わない（詰めると読みにくい）。

### 形と間

- **角丸は 0**（Genius のバーや検索欄と同じ四角）。
- **影は1つだけ**。浮いて見える唯一の要素、PC の設定パネルに付ける。
- **間隔**
  - バーは Genius の行の 16px 下。
  - 前書きはバーの 16px 下に置き、最初の歌詞までは 28px 空ける（スマホは 24px）。
  - 英語と訳のあいだは 2px、訳から次の英語までは 12px（スマホ 10px）。英語と訳が一組に見える比率にしている。

### 前書き

- **ラベルは付けない**。「誰が誰に」「この曲は」をやめ、文そのものが役割を語るようにする。
- **一文目「誰が誰へ」**：「AからBへ」の形の一文（矢印 → は使わない）。プロンプトでこの形を頼む。
- **二文目「この曲は」**：段落の頭を1字下げる（日本語の段落の作法）。
- **2回目以降**：一文目＋下線付きの「続きを読む ▾」だけを出す。これは Genius の「Read More」と同じ文法。

## 6. 歌詞の行

- 訳の行は**背景も線もなし**で、英語の行の真下に置く。Genius の灰色の背景は「Genius の注釈」の印なので、こちらは使わない。
- **確保した空き行（まだ訳していない行）**
  - 「日本語で読む」を押した瞬間に、全行の下に1行分の空きが開く（§8「開く」）。
  - 空きには何も描かない。点線も灰色のバーも、未完成に見えるので使わない。
- **ペン（いま書いている行）**
  - 空き行の左端、最初の文字が来る位置に、太さ 1.5px・高さ 1em の黒い縦線を1本だけ置く。
  - 1.4秒かけてゆっくり明滅する（不透明度 1 → .3 → 1）。打鍵のような点滅ではなく呼吸のようにして、上の行を読んでいる目を引っぱらない。
  - 訳が来ると文字が即座に置かれ、ペンは次の行へ飛ぶ。ペンは常にページに1本だけ。
- **訳し終えた行**：墨色の日本語。フェードインはしない。文字は「現れる」ものではなく「組まれる」もの。
- **アドリブ**：末尾の（イェー、イェー）は控え色、同じ大きさ。
- **繰り返し**：前に出た行の繰り返しは行全体を控え色にする。読めるけれど、すでに読んだ目は飛ばせる。
- **※**
  - 訳の末尾に置くボタン。※は黒、太さ 700、当たり判定は 44×44px。
  - 開いているときは、黄の四角に黒い ※（「尋ねた言葉」の印）。
- **抜け**：――（2倍ダーシ）を控え色で。読み上げは「この行は訳せていません」。
- **継ぎ目（止まった場所）**
  - 頭のバーと同じ黒いバーを、止まった行の直後に繰り返す。左は**続きを訳す**、黄の線は止まった割合のまま。
  - バーの下に理由の一文（13px、控え）。例：長い曲なので、ここで一度区切りました。
  - **継ぎ目より下には空きを作らない**。まだ訳していない部分は、素の Genius に見える。

## 7. 注

- **箱に入れない**。カードも背景も罫線も使わない。**二字下げ**（左に 2em）と一段小さい文字だけで「注」と分かるようにする（和書の注の作法）。
- 各項目は、1行目が見出し、2行目からが説明。
  - **見出し**：Genius の英字で “Sandman” を書き、背景を黄にする。続けて控え色の小さい字で〔引用・元ネタ〕。
  - **説明**：80字以内、14/24px、墨。推測のときは文末に控え色で〔推測〕を付ける。
  - 根拠が Genius の注釈なら、控え色で「Genius注釈より」。
  - 「Geniusの注釈を英語で読む ▾（▲312）」は下線リンク。開くと最大400字の英語を出し、最後に「続きを読む」「注を閉じる」。
- 項目どうしは 12px あける。
- **「尋ねた言葉」の三点セット**：注を開いた瞬間、次の三つが同時に黄になり、目が読まずに対応をつかめる。
  - 歌詞の中のその英語（Genius の文字は書き換えず、Highlight API で黄の背景と黒い 2px の下線を引く）
  - 開いた ※
  - 注の見出し
- **開閉**
  - ※で開閉し、Esc で閉じてフォーカスは ※ に戻る。
  - 別の注を開くと前の注は閉じる。このとき、押した ※ が指の下に残るよう、消えた高さのぶんだけスクロールを戻す。

## 8. 動き

**自動で起きる演出は「完了したら一歩下がる」1つだけ。** 訳し終えると次の順で進み、全体で約0.9秒です。

1. 黄の線が 100% まで伸びる（0.24秒）。
2. 0.28秒止まり、「終わった」ことを見せる。
3. バーが黒から白になり、文字が白から黒になる。状態文は「AIによる日本語訳」に入れ替わり、［止める］は消える（0.36秒）。

箱の大きさとリンクの位置は一切動きません。この演出は訳すたびに1回だけで、2回目以降の表示では最初から白いバーで表示します。

ほかの動きはすべて、読み手の操作への返事です。

- **開く（押した瞬間）**
  - 全行の下に空き行が 0.26秒で開く（`cubic-bezier(0.2,0,0,1)`）。英語の行が分かれて、訳の場所ができる様子が一度だけ見える。
  - 画面の上下 600px 以内の行だけ動かし、残りは瞬時に開く。
  - 続けて、1行目の空きにペンが立つ。
- **待ち（S3）**：黄の短い線（56px）がバーの下端を左から右へ流れる（1.4秒で一往復）。
- **到着中**
  - 黄の線は1行ごとに 0.24秒で伸びる。
  - 前書きは高さ 0.2秒で開く。
  - 訳の文字はフェードしない。
- **注**
  - 場所は瞬時に空く。中身は上から 0.18秒で現れる。
  - 黄の三点は瞬時に付く。閉じるのも瞬時。
- **訳を隠す／表示**：瞬時に切り替える。読んでいた英語の行が画面上の同じ位置に残るよう、スクロールを補正する。
- **設定**
  - PC は不透明度と 4px の下降で 0.16秒。
  - スマホは下から 0.28秒でせり上がり、背景の暗幕は 0.2秒。
- **動きを減らす設定のとき**
  - すべて瞬時に切り替える。
  - ペンは明滅しない。
  - 待ちの線は左端に止めて置く。

## 9. 他の案から移植したもの・捨てたもの

| 由来 | 移植したもの |
|---|---|
| 第一原理 | 「尋ねた言葉」の黄の三点セット／押した瞬間に空き行を開く／画面付近だけ動かす／注を切り替えてもスクロールを戻して指の下を保つ／PC で行数を出す |
| 行間の訓点 | 最初の文字が来る位置で呼吸するペン／注の二字下げ／英語と訳の間を 2px、次の英語までを 12px にする比率 |
| 国内盤 | 〔〕で注の種類を示す／――で抜けを示す／前書きの1字下げ／「AからBへ」の一文／中断より下は素の Genius |
| Genius になじむ案（骨格） | 黒いバー、決まった位置のリンク、黄の進み具合、白への着地、AIによる日本語訳、継ぎ目のバー、システムフォント、赤と緑を使わない設定 |

**捨てたもの**

- 黒い注パネル：歌詞の中でうるさすぎる。
- 明朝体と Web フォント。
- 朱色：却下された A に近く、Genius の色でもない。
- 訳の行全体を押せるようにすること：スクロール中の誤タップと、文字選択の邪魔になる。
- 訳を隠すときのアニメーション：歌いたい瞬間は即座がいい。
- 国内盤案の、常に出しっぱなしの 90px のバー。
- 押せない時間を作って誤タップを防ぐ細工：位置を固定する設計で不要にした。

## 10. 設定シートと初回シート

**共通の形**

- 見出しはバーと同じ黒（PC は 44px、スマホは 48px）で、タイトル 15/700 は白、右に下線付きの「閉じる」。本文は白で、角丸なし。
- PC はポップオーバー：幅 360px。バーの右端に揃えて 8px 下に出す。枠線は 1px の黒、影は1つだけ。
- スマホは下から出るシート（角なし）：最大の高さは画面の 85%、下にセーフエリアの余白、背景に暗幕。

**設定**

- 区切りは間隔 24px と 1px の薄い線（`#E5E5E5`）。線を使うのはここだけ。
- キーの行
  - 左に「Gemini」。
  - 右に状態を**言葉だけで**出す。色の点は使わない。
    - 使えます（黒）
    - 未設定（控え）
    - 今日の枠を使い切りました（{when}から使えます）（控え）
    - キーが使えません（黒、太字、下に理由1行）
    - 確かめています…（控え）
  - 次の行
    - ••••abcd：Genius の数字で、等幅。
    - 下線リンク：キーを入れ直す、キーを消す、キーを作る（Google AI Studio）。
- この曲
  - 「{日付}に{モデル}で訳しました」（モデル名を出すのはここだけ）。
  - 下線リンク「この曲を訳し直す」：押すとその場で確認文に変わる。確認文は「今の訳を残したまま訳し直します。終わると入れ替わります」に、黒の［訳し直す］と下線の「やめる」。
  - 「この曲の訳を消す」も同じ形。
  - 「直近のエラー ▾」：Genius の英字 12px で、等幅フォントは使わない。
- 保存データ
  - 「{n}曲を保存しています（{size}）」。
  - 下線リンク：書き出す、読み込む、すべて消す。
  - すべて消すの確認文：「保存した{n}曲をすべて消します。元に戻せません」に、黒の［すべて消す］と「やめる」。

**初回（日本語訳をはじめる）**

- 手順は2つ。番号は 24×24 の黒い四角に白い数字（バーと同じ文法）。
- 手順1：Google AI Studio を開き、Googleアカウントでログインして無料のAPIキーを作ります。続けて下線リンク「Google AI Studio を開く」。
- 手順2：キーをコピーして、下に貼り付けます。続けて入力欄（48px、1px 黒枠、プレースホルダー「ここに貼り付け」）。
- 「キーはこのブラウザのユーザースクリプト保存領域にだけ置かれ、Google 以外には送られません」（13px、控え）。
- 主ボタン：黒の［保存してこの曲を訳す］。スマホでは幅いっぱい、高さ 48px。
  - **押せない状態にしない**。空のまま押したら入力欄にフォーカスし、ひとこと案内を出す。
  - 貼り付けた時点でキーを確かめる。
- 下に下線の「保存だけする」。
- **ダーク**
  - シート：`#1C1C1C`、文字は `#F2F2F2`、控えは `#A3A3A3`、区切り線は `#333`。
  - 主ボタンは反転（白地に黒文字）。見出しのバーは黒のまま。

## 11. 文言の変更

- 「·」でつなぐ書き方をやめる。
  - 例：訳し直しています · 終わるまで今の訳を表示します → 文を分け、補足の1行へ。
  - 保存した曲：{n}曲 · {size} → {n}曲を保存しています（{size}）
- 別の曲（{title}）を訳しています → 別の曲を訳しています ＋「{title}」が終わると、この曲も訳せます
- 今日の無料枠は終わりました。明日 16:00 から訳せます → 今日の無料枠を使い切りました ＋ 明日の16:00から、また訳せます
- 途中まで訳してあります（31/67行） → 67行のうち31行まで訳してあります
- 失敗後の「日本語で読む」 → **もう一度訳す**
- 前書きのラベル（誰が誰に／この曲は）と矢印 → ラベルなし、「AからBへ」
- 注の種類を見出しの上に置く → 英語の後ろに〔スラング〕
- 推測のタグ → 文末に〔推測〕
- Geniusの注釈（英語）▲{n} → Geniusの注釈を英語で読む ▾（▲{n}）
- 抜けの印 — → ――
- 新しく足す文言
  - AIによる日本語訳
  - 訳を隠しています
  - 注を閉じる
  - 確認文2つ（訳し直す、すべて消す）

## 12. 品質の床（デザインの一部として守ること）

- **コントラスト**：本文 15:1、控え 5.3:1、黒地のリンク 11:1。黄は黒い字の背景、または黒地の上の線にだけ使う。
- **フォーカス**：白地では 2px 黒（2px 離す）、黒地では 3px 黄（内側 4px）。
- **当たり判定**：バーのリンクは高さ 48px。※は 44×44px。
- **スマホ**
  - スクロールで出す要素は上端に 140px あける（Genius の固定ヘッダー約125px のため）。
  - バーの文言は折り返さない長さに抑える。
- **読み上げ**
  - バーは「Lyric Lens 日本語訳」という領域にする。
  - 状態の変化だけを丁寧に読み上げる（訳し始めました／訳し終えました／止まった理由／訳を隠しました）。1行ごとには読まない。
  - 進み具合は progressbar として読ませる。
- **性能**
  - Web フォントなし。
  - 開く演出は画面付近だけ。
  - 1行ごとのフェードはしない。
  - 2回目以降の表示はバーも訳も同じフレームで描く。
- **Genius の変化への備え**
  - 英字フォントは起動時に読み取る。
  - 再描画されたら差し込み直す（今の仕組みのまま）。
  - タップが Genius の注釈を開かないよう、クリックはこちらで止める。
- **訳を隠す**：曲ごとに覚える。歌いたい曲は次も隠したまま開く。

## 13. まだ確かめること（見本と実機で）

1. 黒いバー（S2）が広告や「おすすめ」のバーに見えないか。初見の人で確かめる。
2. 訳し終えてバーが白くなったとき、読み手が戸惑わないか。
3. Genius 自身が注釈を開いたときの黄色と、こちらの黄が混乱しないか（実ページで確認）。
4. 日本語 16px と英語 18px のバランス。
5. Windows で BIZ UDPゴシックがない環境での見え方。
6. スマホのバーで、いちばん長い文言でも折り返さないか。

## 14. 見直し（ありがちなデザインになっていないか）

| ありがちな型 | この設計では |
|---|---|
| クリーム色の背景、テラコッタの差し色 | 使わない。色は Genius 自身の黒・白・黄と、無彩色の灰だけ |
| 同じ角丸カードを並べる、同じ影 | カードは使わない。角は 0、影は浮く1か所だけ |
| 大文字の小見出し、「·」つなぎ、→ 付きのボタン | 使わない。ラベルは出所を示す「AIによる日本語訳」の1つだけ |
| 等幅の小さいラベル | 使わない。数字は Genius の字の等幅数字 |
| あちこちのフェードイン | しない。自動の演出は完了時の1つだけ |
| 「黒＋黄＝ありがちな Genius 風」 | ホストの文法を借りつつ、黒＝Lyric Lens が話している、黄＝尋ねた言葉、と意味を一つずつ持たせ、それ以外では使わない |

**この見直しで最初の案から変えた点**

- **注の黒いパネルをやめた**：歌詞の流れの中でいちばんうるさい物になっていた。
- **点滅する「…」をペンに替えた**：最初の文字が来る位置を正直に示せる。
- **空き行を「最初の返事が来た瞬間」ではなく「押した瞬間」に開くようにした**：画面の変化を読み手の操作の直後だけにするため。
